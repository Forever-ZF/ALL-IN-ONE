## 核心结论

| 项 | 结论 |
|---|---|
| 最优路径 | **C：先接单 → 再产品化**（垂直 B 端 + 托管代运营），不是先做 SaaS |
| 90 天现实里程碑 | 8 个付费客户，月收入 0–3000 元 |
| 90 天不现实的目标 | 月入过万（3 年期的 P30 事件） |
| 5000 元用途 | 买一个「能被验证的最小闭环」，不投流量 |
| 最大风险 | 获客（60% 的国内 OPC 把获客与销售列为最大困难） |

## 报告里的五块硬内容

1. **期望值校准** —— 三组独立数据交叉：Stringers 的 11,637 个产品**支付平台真实流水**（不是问卷）、
   《中国企业家》148 份问卷、复旦 1500 份问卷、127 位 OPC 创业者 3 年追踪。
2. **五条硬约束** —— 个人主体做不了经营性 ICP 备案；个体户近乎零成本；
   **面向公众做 AI 功能要算法备案 + 大模型登记（2–8 个月），做签约客户制则通常不需要**；
   欧美获客打法在大陆失效的逐项对照；投流是净亏损。
3. **5000 元分配表** —— 含「绝对不投清单」，以及境内 / 境外服务器的取舍。
4. **选品公式 + 8 个候选品类排名** —— 每项给可实现的点与缺点，附**国内真实价格锚**（¥68 / ¥168 / ¥368 的一次性脚本 vs ¥30–100/月订阅）。
5. **90 天执行计划 + 风险止损信号** —— 第 30 / 60 / 90 天三个检查点，以及 8 条止损规则。

## 方法论备注

这份报告刻意**不用** Starter Story 的头条收入作为基准。原因写在上一份报告的「七重校准」里：
那个库 62% 的收入是研究 agent 的估算，没有第三方审计。本报告改用
**支付平台只读密钥产生的真实流水**作为基准，可信度高一档。
